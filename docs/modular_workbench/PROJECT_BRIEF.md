# 稳定项目说明

项目提供一个正式 `cumcm-modeling-evidence` Skill和一个共享证据内核，覆盖接题到论文组技术交接。
它不训练基础模型，也不生成最终论文、成品图、排版或提交压缩包。模型效果必须由当前输入、
真实Run、独立核验与有界Claim支持；通过软件测试不能证明陌生题泛化或真实未来精度。

未来默认 `GUIDED_SINGLE_MODULE`。`GUIDED_LOCAL` 允许用户主导正常开发，保留数据事实、
信息可见性、失败和Final隔离，不继承某次评测的固定四次请求或远端pre-run push。
`LAB_EVAL` 保留登记的评测、污染、预算和终局。旧case不能改模式逃避历史。
工具开发仓库与实际case分离，case材料、审查包及本地代码Git不自动上传；不自动改remote。

人员接口：新网页大脑协调当前工作，旧对话供历史咨询；Codex主执行且本地事实唯一。
队员主导研究、逐项核验、决定写作与提交，并承担结果责任；原生只读审查和独立Python复算
分别记录。机器技术拒绝不能由任何角色改成PASS。

2026规则核对只阅读官方规则页面，未读取当届赛题。官方AI工具规定强调团队主导、逐项核验、
使用披露和支撑材料中的详细说明；竞赛章程限制赛期队外讨论以及当前题目资料的公开传播。
具体使用以官方当前规则和组织方要求为准；本工具不代替队员合规审查。
来源：[AI工具规定](https://www.mcm.edu.cn/html_cn/node/fef94648f2836ab6cc81586f4c38512b.html)、
[竞赛章程](https://www.mcm.edu.cn/html_cn/node/9d8e511fe7a1447b35f53a82c908e2e0.html)。

论文团队收到逐问技术事实和证据：文字组组织模型与结论表述；数据图组使用同一Run的
figure-ready data并保留单位、样本和误差含义；模型示意图组依据已确认对象和依赖绘图；
表格组核对每个数字与口径；排版组安排版式与引用；提交组负责文件、匿名、附件和AI披露。
这些职责各有接口，不能把示意图当数值证据、把美化后的图表当原始数据，也不重写队友Skill。

历史RC8资格、RC9拒绝、Validation0/2与旧Development0/2只按各自冻结版本解释。
本轮新建设的验收与交付在独立结果目录记录；真实网页/队员验收、Windows原生运行、
新盲测、保留题、基础模型训练和最终论文均不因建设演练自动成立。
