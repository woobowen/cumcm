# Cross-case gap matrix and generalized repair

This matrix is based on the two real historical C Development regressions and
the independent read-only review. It does not alter the historical frozen
Validation artifacts.

| observed gap | 2021 evidence | 2022 evidence | generalized disposition |
| --- | --- | --- | --- |
| Development evidence could be confused with Final test access | comparison claimed one authorized access although no ledger existed | same route shape and same contradiction | fixed in the core comparison contract with explicit zero-access Development mode and neutral positive/negative cases |
| every requirement was emitted as `DESCRIPTIVE` | 17 requirements, including feasibility and conditional optimization claims | 13 requirements, including classifier and conditional backcasts | replace silent default with explicit case-adapter semantics; no Development claim is marked `PREDICTIVE` without Final evidence |
| engineering/data gate could be read as scientific quality | selected plan passed route gates but had a tolerance-sized receipt gap and an upper-bound cardinality | zero fixed-split Brier loss had only 12 validation groups and no unknown labels | persist `PROVISIONAL_ENGINEERING_REGRESSION`, data/provenance basis, diagnostics, and limitations; keep scientific quality separate from route PASS |
| model-specific risk | mean-greedy wins the registered time metric but is not a global minimum | distance KNN is perfectly accurate but probability-calibration/external-validity status is unresolved | retain case-owned modeling diagnostics; do not encode years, fields, answers, or values in the generic Skill |

The repaired generic path is still one route: it derives stage status from the
actual state history, records observed timing and code identity, validates
Development access semantics, and requires an explicit semantic adapter before
building a Claim bundle. No gate is deleted or weakened.

## Remaining boundary

The current candidate is not a formal release. A fresh Validation case cannot
be registered until the release identity, rubric, registry entry, answer-sealed
pre-run freeze, remote receipt, and clean-context worker are all present. The
absence of 2016/2015 registry entries is recorded as a blocker, not silently
repaired by accessing their problem files.
