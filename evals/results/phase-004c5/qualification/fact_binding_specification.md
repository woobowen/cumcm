# RC8 neutral scientific fact-binding specification

Frozen before implementation, following the independent native early audit of the inherited PR.
The actual CLI/controller must reject scope expansion, statement replacement, source hashes with no
actual bound input, absent metric aliases, hand-written feasibility/causal/simulation predicates,
unresolved contradiction, stale evidence and cross-Run substitution. The same protection applies to
the direct Development completion/semantic-check path. Missing facts mean UNKNOWN/INSUFFICIENT;
the case adapter cannot confer SUPPORTED. Existing P0 timing/ownership and zero-Final Development
boundaries remain protected.

Positive families to close before candidate acceptance: bounded descriptive statistics on real
fields; empirical inputs used in registered conditional simulation; independently recomputed
feasible optimization without an invented prediction test set; mixed per-requirement/portfolio
selection; legitimate Development engineering export with no final access; authorized predictive
evaluation. Their negative pairs include simulation promoted to external empirical effect, assumed
input promoted to observed fact, model-generation semantics renamed to DESCRIPTIVE, missing source
coverage, false independent-check declarations, Final code/input drift and visible-result retry.

Evidence representation uses existing source/data-audit/Run/capture/semantic records. Source class
describes origin; generated-result method and Claim scope describe inference. Every output's proposed
scientific Claim binds source IDs, exact inputs/fields, generation method, scope, assumptions and
computed metrics. Semantic proposals bind the captured statement and may only narrow supported
scope. Registered conditional scope is distinct from observation scope. Independent computational
verification must have real execution, a distinct frozen checker entrypoint and input/output/code
lineage; JSON true alone cannot prove it. Independence of the algorithm and scientific adequacy
also require native review, and are not proven by different filenames or hashes.

Implement these checks within the existing Skill/controller, with a minimal capture helper if
needed; no second Skill or parallel state machine. The pure historical contract functions retain
their historical role, but current executable completion paths cannot use them as scientific
acceptance. Old subject behavior is checked under original Git blobs. New fixes do not rewrite the
old expected hashes or promote historical negative verdicts.

Qualification requires both this fixed risk matrix and realistic positive controller executions.
Freezing this specification does not claim that the implementation or scientific checks pass.
