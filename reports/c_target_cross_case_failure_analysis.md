# C-Target Cross-Case Failure Analysis

## Reference boundary

After the all-case remote unlock, exactly two sources per case were accessed: the official problem
page and one DOI-registered published follow-up analysis. Reference bodies remain under ignored
case-local `references/` directories. Only metadata, hashes, access times, evaluation use, gap
summaries and a no-copy declaration are tracked. No reference code, parameters, formulas, prose or
results entered the formal Skill or replaced a first run.

The references expose plausible alternative portfolios: discriminant/classification/correlation
analysis for a composition problem; evaluation, loss forecasting and constrained allocation for a
supply problem; and risk prediction plus amount/rate decisions for a credit problem. Model-family
differences are not failures. The audit judges requirement satisfaction, mathematical validity,
numerical credibility, real execution, evidence sufficiency and contest-time feasibility.

## Cross-case decision

One defect satisfies RC4 admission. The full selected-output contract was repaired before execution
in the 2021 and 2020 cases, yet no first-class reusable preflight existed. It escaped the 2022
implementation and became a noncompensable Stage-11 failure only after nine Runs were sealed. The
same architecture-level defect independently affected classification, optimization and
prediction-to-decision work. It is both repeated and, when discovered after seal, a universal hard
failure because downstream Claim/handoff evidence is missing.

RC4 is authorized for one neutral change set:

1. one generic selected-output structural validator;
2. one pre-run CLI check for a non-result contract probe before experiment freeze;
3. reuse of the same validator on every successful `execute` output;
4. neutral prediction/optimization fault tests and anti-hardcoding checks.

The change may require only architecture-level fields and shapes. It may not contain a year, problem
identifier/title, attachment, entity, source field, model family, problem parameter, reference
formula or answer.

## Rejected Skill changes

- The infeasible 2021 baseline remains a case-specific modeling failure. The existing mandatory
  successful-baseline Gate behaved correctly; regression must design a feasible baseline.
- The 2021 test-access block remains fail-closed. The Skill must not infer authorization or weaken
  leakage protection after a failed comparison.
- Sparse inverse identifiability and a perfect small-split classification score remain bounded 2022
  limitations, not universal thresholds.
- Published reference methods are alternatives, not oracles. Their names, parameters and formulas
  must not enter the Skill.
