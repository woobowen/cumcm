# M12 最终核验

目的：调用公共controller冻结前置、记录真实STARTED并做独立Final；核验receipt后停。

既有workflow：[说明](../../workflows/final_run.md)。
最少用户输入：比较/稳健性/语义proposal；冻结Final授权范围。case/module/scope由用户指定，内部身份由工具定位。
前置模块：M11。仅接受当前范围且hash一致的前置；缺少时明确拒绝。

允许工具：Codex阅读、一般资料研究（遵守case policy）、本地Python及既有公共CLI。
禁止：把prepare算作研究完成；自动推进下一个模块；覆盖原始输入/历史Run；以网页意见或多数票代替证据。

产物：final_result，及独立work report和本地审查包。
工程核验：身份、前置、实际文件hash与适用core gate；原生状态终点：FINAL_CANDIDATE。
科学审查：独立核验是否验证原目标？失败预算是否被保留？
完成的含义：Final状态依实际账本；不自动接受结论或交接。

停止：M12返回产物及审查包后停止；下一模块必须由用户明确调用。
恢复：先status/resume核对原请求与文件hash；失败保留。已改变输入通过revision创建新root，不覆盖旧Run或已消费Final。
下游影响：只沿当前requirement的实际依赖传播STALE；改变共享输入会影响所有使用者。

可复制给Codex的请求：

```text
case=DEMO-WATER module=M12 scope=REQ-A,REQ-B,REQ-C；仅执行本模块，导出本地审查包后停止。
先读取正式Skill与本任务卡。调用公共controller冻结前置、记录真实STARTED并做独立Final；核验receipt后停。
使用prepare登记请求，在模块内实际分析/编码/核验，再complete核验并导出审查包。
如未知或缺前置，报告具体缺口；不要猜内部hash，不补做未授权模块。
```

真实入口（REQ编号是用户可读请求名，可替换；CASE_ROOT须为独立工作区）：

```bash
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py prepare --case-root <CASE_ROOT> --module M12 --scope ALL --request-id REQ-M12
# Codex现在实际完成M12工作。prepare只生成任务，不运行研究或模型。
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py complete --case-root <CASE_ROOT> --request REQ-M12 --report work/M12.json
```

M09使用run的model/checker操作；M10–M14在complete之前显式执行run的controller操作。
