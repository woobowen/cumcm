# M03 专业研究

目的：Codex实际阅读一般资料并记录来源到具体决策；离线或未核实必须明说。

既有workflow：[说明](../../workflows/research_and_sources.md)。
最少用户输入：概念缺口；允许的专业资料或检索政策。case/module/scope由用户指定，内部身份由工具定位。
前置模块：M02。仅接受当前范围且hash一致的前置；缺少时明确拒绝。

允许工具：Codex阅读、一般资料研究（遵守case policy）、本地Python及既有公共CLI。
禁止：把prepare算作研究完成；自动推进下一个模块；覆盖原始输入/历史Run；以网页意见或多数票代替证据。

产物：research_plan, source_ledger，及独立work report和本地审查包。
工程核验：身份、前置、实际文件hash与适用core gate；原生状态终点：SOURCES_PLANNED。
科学审查：来源是否真支持所采用的方法与假设？哪些知识仍未知？
完成的含义：研究分析完成；外部事实按核验范围报告。

停止：M03返回产物及审查包后停止；下一模块必须由用户明确调用。
恢复：先status/resume核对原请求与文件hash；失败保留。已改变输入通过revision创建新root，不覆盖旧Run或已消费Final。
下游影响：只沿当前requirement的实际依赖传播STALE；改变共享输入会影响所有使用者。

可复制给Codex的请求：

```text
case=DEMO-WATER module=M03 scope=REQ-A,REQ-B,REQ-C；仅执行本模块，导出本地审查包后停止。
先读取正式Skill与本任务卡。Codex实际阅读一般资料并记录来源到具体决策；离线或未核实必须明说。
使用prepare登记请求，在模块内实际分析/编码/核验，再complete核验并导出审查包。
如未知或缺前置，报告具体缺口；不要猜内部hash，不补做未授权模块。
```

真实入口（REQ编号是用户可读请求名，可替换；CASE_ROOT须为独立工作区）：

```bash
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py prepare --case-root <CASE_ROOT> --module M03 --scope ALL --request-id REQ-M03
# Codex现在实际完成M03工作。prepare只生成任务，不运行研究或模型。
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py complete --case-root <CASE_ROOT> --request REQ-M03 --report work/M03.json
```

M09使用run的model/checker操作；M10–M14在complete之前显式执行run的controller操作。
真实命令的实测范围与结果见[Runbook](../../../../../docs/modular_workbench/RUNBOOK.md)。
