# M01 题目接收

目的：核对原件、表注和附件关系，登记字节hash，阅读并写完整题意概述。

既有workflow：[说明](../../workflows/problem_intake.md)。
最少用户输入：原题与附件；case ID；本次范围。case/module/scope由用户指定，内部身份由工具定位。
前置模块：无。仅接受当前范围且hash一致的前置；缺少时明确拒绝。

允许工具：Codex阅读、一般资料研究（遵守case policy）、本地Python及既有公共CLI。
禁止：把prepare算作研究完成；自动推进下一个模块；覆盖原始输入/历史Run；以网页意见或多数票代替证据。

产物：work report所指的真实原件/代码/capture，及独立work report和本地审查包。
工程核验：身份、前置、实际文件hash与适用core gate；原生状态终点：保持当前原生状态；核验本模块产物。
科学审查：原题、附件是否完整？是否遗漏表注或模板？
完成的含义：原件登记与题意概述；尚未建模。

停止：M01返回产物及审查包后停止；下一模块必须由用户明确调用。
恢复：先status/resume核对原请求与文件hash；失败保留。已改变输入通过revision创建新root，不覆盖旧Run或已消费Final。
下游影响：只沿当前requirement的实际依赖传播STALE；改变共享输入会影响所有使用者。

可复制给Codex的请求：

```text
case=DEMO-WATER module=M01 scope=REQ-A,REQ-B,REQ-C；仅执行本模块，导出本地审查包后停止。
先读取正式Skill与本任务卡。核对原件、表注和附件关系，登记字节hash，阅读并写完整题意概述。
使用prepare登记请求，在模块内实际分析/编码/核验，再complete核验并导出审查包。
如未知或缺前置，报告具体缺口；不要猜内部hash，不补做未授权模块。
```

真实入口（REQ编号是用户可读请求名，可替换；CASE_ROOT须为独立工作区）：

```bash
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py prepare --case-root <CASE_ROOT> --module M01 --scope ALL --request-id REQ-M01
# Codex现在实际完成M01工作。prepare只生成任务，不运行研究或模型。
.venv/bin/python .agents/skills/cumcm-modeling-evidence/scripts/cumcm_workbench.py complete --case-root <CASE_ROOT> --request REQ-M01 --report work/M01.json
```

M09使用run的model/checker操作；M10–M14在complete之前显式执行run的controller操作。
真实命令的实测范围与结果见[Runbook](../../../../../docs/modular_workbench/RUNBOOK.md)。
